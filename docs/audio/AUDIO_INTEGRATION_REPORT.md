## Resource naming and the one collision

Every delivered take becomes one sound resource named after its file (`snd_sword_hit_1.wav` → `snd_sword_hit_1`). The stable event ID (`snd_sword_hit`) is the catalog key and the only name gameplay code uses. Voice takes (`snd_voice_dave_1` …) are individual IDs. The template already owns a resource called `snd_player_defeated`; it keeps its name and the delivered take is imported as **`snd_player_defeated_1`** (explicit mapping in the catalog). No other name collides with the 26 template sounds.

## Loading settings

| Group | GameMaker compression | Why |
|---|---|---|
| Looping music (`mus_desert`, `mus_pharaoh`) and all looping SFX | 0, uncompressed | sample-accurate whole-file seams |
| One-shot music (`mus_intro`, `mus_boss_defeat`, `mus_ending`, `mus_gameover`) | 1, compressed (not streamed) | smaller package; never loops |
| SFX and dialogue blips | 0, uncompressed | instant start |

All resources use `audiogroup_default`, 16-bit, the delivered sample rate and channel layout. The seven loops repeat their whole file (`audio_play_sound(..., loop=true)`); the sidecar points are 0 to file end, so no `audio_sound_loop_start/end` override is needed. Fades happen only when a loop starts or stops (owned-loop envelopes), never on each repeat.

## Runtime service (scripts/scr_audio)

- Catalog: `datafiles/data/audio_catalog.json`, derived from `AUDIO_CUE_SHEET.csv` (gain dB, bus, per-emitter and global limits, minimum retrigger, priority, loop, fade in/out) and `AUDIO_MANIFEST.json` (files). Prompts and review metadata are not shipped.
- Gain: `10^(dB/20)` × user bus volume (music / SFX / dialogue blips) × duck × distance attenuation, applied once at playback; sources are untouched. Cue-sheet values are used as delivered; **no gain changes were made** because no listening pass was possible.
- Budgets: SFX 24 (weather included); within it warnings 6, movement 6, projectile travel 4, weather 1; dialogue 1 across all speakers; music 1, or 2 during a crossfade. Requests over a limit or inside a cooldown are **dropped, never queued**. When a budget is full, the lowest-priority un-owned voice below the new priority is stopped; otherwise the request is dropped.
- Variants: random pick that never repeats the previous take of the same ID.
- Loops: started by owner key (`weather`, `boss:laser`, `w:<instance>`, `w:proj:<instance>`); starting an owned loop again returns the existing handle. Owners stop their loops on hit, expiry, destroy, Clean Up, death, load, scene unload, skip and menu return.
- Ducking: text lowers music 4 dB and wind 8 dB (≈100 ms attack, 350 ms release); attack warnings lower music 3 dB and weather 6 dB (≈30/250 ms). The stronger reduction wins; ducks are not summed.
- Positional: world SFX are attenuated by distance from the camera centre (full within 360 px, silent beyond ≈1260 px). **No stereo panning** is applied (deliberate: listener orientation could not be verified without a runtime). Music, UI, text and Dave's own cues are unspatialised.
- Pause: world-owned voices pause while inventory, pause, dialogue or an in-scene cinematic stops the world, and resume afterwards; music, UI, blips and the wind bed keep playing. Nothing builds a backlog.
- Blips: one global voice, a blip every second newly revealed letter or digit, takes never repeat back-to-back, pitch 0.94–1.06, at least 75 ms between onsets, occupied voice = dropped. Comma/semicolon pause 120 ms, sentence/ellipsis 240 ms. Instant reveal, page/line change, skip and scene exit cancel the active blip with a 5 ms fade. Objective toasts, UI text and the ending title are silent.

| Completed-boss load | no defeat, gate or reward cue is replayed. |
